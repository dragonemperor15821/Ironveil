ROOT CAUSE OF INVISIBLE TERRAIN (TASK 1)
================================================

The diagnostic report from the initial batch-mode run confirmed that all 16 terrain
chunks were generated successfully with 0.000000 m shared-edge height differences and
16/16 TerrainCollider/TerrainData matches. However, the Unity Scene view showed only
an empty grid.

Investigation revealed the following causes:

1. Terrain generation occurs during Play Mode, not Edit Mode. The prototype's
   GeneratePrototype() coroutine creates terrain chunks incrementally across frames.

2. The prototype camera (set via FramePrototypeCamera()) frames the complete 1200x1200
   world, but this only activates when Entering Play Mode.

3. The terrain is not visible in Edit Mode because generation is deferred to Play Mode.

SOLUTION: Open Ironveil - WorldGeneration Test scene and enter Play Mode. The terrain
will generate, the prototype camera will frame the world, and all 16 terrain tiles will
be visible in both Scene and Game views.

Alternatively, use the Edit Mode workflow: select the World Generation Prototype object
and click "Generate / Refresh Terrain Preview" in the Inspector. This builds a transient
Scene-view preview without entering Play Mode.

KEY ARCHITECTURE: MULTI-TERRAIN QUERY SYSTEM (TASK 2)

The WorldTerrainQueryProvider is a cached, opt-in system that allows existing
systems (BaseSpawner, RiverGenerator, RailGenerator) to query terrain height,
slope, and normal at world positions across 16 generated Unity Terrain tiles.

Architecture:
- SetTerrainTiles(IReadOnlyList<Terrain>, Vector2, int, int): Builds a
  collider[,]/Bounds[,] grid from the 16 generated terrain chunks. Validates that
  all colliders are enabled and use matching TerrainData. Computes grid origin,
  column/row counts, tile size, and boundary extremes.

- TryRaycastDown(Vector3, float, out RaycastHit): Raycasts down from a world
  XZ point through the cached tile grid. At exact tile boundaries, adjacent tiles
  are tried to avoid precision gaps. Returns false for points outside the world
  bounds.

- TryGetHeightAndNormal(Vector3, float, out float, out Vector3): Public API that
  uses TryRaycastDown to return terrain height and normal at a world position.

- Cached tile layout: 4x4 grid, 300-unit tiles, 1200x1200 world origin at (-600,-600).
  Tile (z,x) corresponds to terrain at position (originX + x*tileSizeX, 0,
  originZ + z*tileSizeZ).

- Performance: No scene-wide searches during query. Cache is built once after
  terrain generation. Queries are O(1) with at most 9 tile checks (primary +
  neighbors).

- Integration: BaseSpawner, RiverGenerator, and RailGenerator each have a
  SetTerrainQueryProvider() method. The prototype automatically calls this after
  SetTerrainTiles(). The providers are shared singletons (active = this pattern).

ATTEMPTED 350-BASE SPAWNING TEST (TASKS 3-4)
================================================

The prototype was configured to run the production BaseSpawner with the exact 350-base
distribution:
- Tank: 110, Heli: 90, Air: 80, Naval: 25, Rail: 17, Heli Naval: 11, Heli Rail: 7,
  Air Naval: 6, Air Rail: 4, TOTAL: 350

Test runs were performed using Unity batch mode with the controlled play mode runner.
Terrain generation succeeded (16/16 chunks, seed 12345 reproducibility verified).
However, the River/Rail route generation consistently failed because the
WorldTerrainQueryProvider's TryRaycastDown() could not hit route evaluation points.

This is the primary blocker for the 350-base spawning test. The base cause is that
the route guide control points from BuildGeographicLayout() produce XZ positions
where the provider's raycasts fail (likely tile boundary or height-related issues).
The fallback terrain-sampled route generation (GenerateFallbackRiver/GenerateFallbackRail)
was implemented but not fully validated through the play mode test.

What was verified:
- Land base placement can run independently of River/Rail routes
- 16/16 terrain chunks generate correctly with 0.000000 m seam errors
- Heightmap resolution 513 per chunk, seed/data reproducibility PASS (max 0.00427 m error)
- 4867 land candidate sites identified (target: 322)
- Naval guide slots: 910 estimated (target: 53)
- Rail guide slots: 448 estimated (target: 35)
- All screening targets met but NOT a BaseSpawner certification (as documented)

What still needs completion:
- River/Rail route generation must work for Naval and Rail base placement
- The 350-base run with all variant types (including Naval over water, Rail on track)
- Exact rejection reasons and frequencies for all 350 bases
- Naval hangar positioning over actual river meshes
- Rail hangar alignment with actual railway geometry
